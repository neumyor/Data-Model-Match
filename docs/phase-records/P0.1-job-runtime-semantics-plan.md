# P0.1 Job 运行时语义补充计划

## 目标

冻结并测试视觉语义 Profile/Match job 的重试、取消、worker 恢复、SSE 重放和发布语义，使主 Agent 后续共享 `ResourceStore`、HTTP 与 SSE wiring 不需要临时决定公共行为。

## 非目标

- 不修改 `ResourceStore`、CLI、HTTP、SSE transport、前端或公开 v1 JSON Schema。
- 不实现生产 worker、定时器、队列或真实模型调用。
- 不改变已冻结的 endpoint、状态枚举、idempotency key 或旧资源 API。

## 输入

- `docs/dataset-management-ui-phased-acceptance.md` v1.2。
- `docs/semantic-contracts/semantic-contract-rfc.md`。
- v1 ErrorCode、Job、SSE、VLM configuration Schema。

## 输出

- `docs/semantic-contracts/job-runtime-semantics-v1.json`。
- RFC 的 P0.1 运行时语义补充。
- 独立契约测试，验证错误码映射、attempt/retry、取消/发布、worker lease、SSE retention/replay 与恢复协议。

## 所有权

- `ownedPaths`：本计划、P0.1 报告、`docs/semantic-contracts/job-runtime-semantics-v1.json`、`docs/semantic-contracts/semantic-contract-rfc.md`、`tests/semantic_contracts/test_job_runtime_semantics.py`、Phase 0 执行记录。
- `readOnlyPaths`：其余 v1 契约、`semantic_store.py`、现有测试。
- `forbiddenPaths`：共享生产路径、`config.llm.json`、`_reference_only/`。

## 验收

1. 策略完整覆盖现有 ErrorCode 枚举且每项有确定 retryable 决策。
2. `attempt`、`maxAttempts`、退避/jitter 和 retry eligibility 可在无时钟、无网络条件下复算。
3. 取消/发布、worker lease/recovery、SSE retention/replay 和崩溃恢复有明确唯一的胜负规则。
4. RFC、策略、Schema ErrorCode 和测试无漂移。
5. 契约测试与现有 semantic store 测试通过，且 Phase 0 执行记录登记独立复核结果。
